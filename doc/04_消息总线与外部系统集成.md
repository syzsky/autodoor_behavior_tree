# 消息总线与外部系统集成 — 实现文档

## 1 概述

### 1.1 目标

在核心行为树引擎基础上，新增进程内消息总线、外部系统适配器层、服务层和 REST/WebSocket 服务端，使行为树具备与外部系统通信、被远程控制和发布/订阅事件的能力。同时接入平台认证体系，支持用户登录与权限管理。

## 2 消息总线 (bt_bus/)

### 2.1 MessageBus 单例

**文件**: `bt_bus/message_bus.py`

`MessageBus` 采用双重检查锁定单例模式，提供进程内消息发布/订阅能力。

**核心 API**:

| 方法 | 签名 | 说明 |
|------|------|------|
| `publish()` | `publish(topic: str, data: Any, headers: dict = None, source: str = "") -> str` | 发布消息，返回消息 ID |
| `subscribe()` | `subscribe(topic_pattern: str, callback: Callable) -> str` | 订阅主题，返回订阅 ID |
| `unsubscribe()` | `unsubscribe(subscription_id: str) -> None` | 取消订阅 |
| `request()` | `request(topic: str, data: Any, timeout_ms: int = 5000) -> Optional[Message]` | 请求-响应模式 |
| `subscribe_async()` | `subscribe_async(topic_pattern: str) -> (asyncio.Queue, str)` | 异步订阅（供 FastAPI/SSE 使用） |
| `add_middleware()` | `add_middleware(middleware) -> None` | 添加中间件到责任链 |
| `set_engine_thread_id()` | `set_engine_thread_id(thread_id: int) -> None` | 标记引擎线程（防死锁） |
| `set_event_loop()` | `set_event_loop(loop) -> None` | 注入 asyncio 事件循环（供异步分发） |

**防死锁机制**: `request()` 方法在调用前检查当前线程是否为引擎线程（通过 `set_engine_thread_id()` 注册）。若在引擎线程中调用，自动降级为 `publish()`，避免引擎线程阻塞导致行为树卡死。

### 2.2 消息格式

**文件**: `bt_bus/message.py`

```python
@dataclass
class Message:
    id: str                        # uuid4
    topic: str                     # 点分层次主题，如 bt.1.event.tree.started
    data: Any                      # JSON 兼容数据
    headers: dict                  # 元数据（含认证信息）
    timestamp: float               # 创建时间戳
    source: str                    # 来源标识
    priority: MessagePriority      # LOW/NORMAL/HIGH/URGENT
    reply_to: Optional[str]        # 回复主题（请求-响应模式）
    correlation_id: Optional[str]  # 关联 ID
```

**主题命名规范**: `bt.{tree_id}.{category}.{subject}`

示例:
- `bt.1.event.tree.started` — 树1启动事件
- `bt.1.event.node.status_changed` — 树1节点状态变化
- `bt.1.data.blackboard.changed` — 树1黑板变量变更
- `bt.default.command.tree.start` — 树控制命令

### 2.3 主题路由器

**文件**: `bt_bus/topic.py`

`TopicRouter` 维护 `pattern -> [Subscription]` 映射，支持通配符匹配：

| 通配符 | 含义 | 示例 |
|--------|------|------|
| `*` | 匹配单层 | `bt.1.event.*` 匹配 `bt.1.event.started`，不匹配 `bt.1.event.node.changed` |
| `**` | 匹配多层 | `bt.1.event.**` 匹配 `bt.1.event.node.changed` |
| 精确 | 完全匹配 | `bt.1.event.tree.started` 仅匹配自身 |

### 2.4 中间件链（责任链模式）

**文件**: `bt_bus/middleware.py`

所有中间件继承 `Middleware` 基类，实现 `process(message, next_handler)` 方法。中间件按添加顺序逆序包装，形成责任链。

| 中间件 | 说明 |
|--------|------|
| `LoggingMiddleware` | 记录消息发布和处理日志 |
| `ValidationMiddleware` | 验证消息 topic 和 data 非空 |
| `RateLimitMiddleware` | 令牌桶限流（默认 100 条/秒） |
| `AuthMiddleware` | 从 headers 提取 Token 进行认证，注入 principal 信息 |

### 2.5 死信队列

**文件**: `bt_bus/dead_letter.py`

`DeadLetterQueue` 存储无法处理的消息（无订阅者、订阅者异常），最大容量 1000 条，环形覆盖。

死信原因:
- `NO_SUBSCRIBER` — 无匹配订阅者
- `SUBSCRIBER_EXCEPTION` — 订阅者回调抛出异常

### 2.6 总线统计

**文件**: `bt_bus/stats.py`

`BusStats` 按主题记录发布计数和投递计数，提供 `get_summary()` 汇总方法。

### 2.7 共享线程池

**文件**: `bt_bus/thread_pool.py`

`SharedThreadPool` 全局单例，按任务类型分配信号量配额，避免多个独立线程池在 GIL 下竞争。

| 任务类型 | 配额 | 用途 |
|---------|------|------|
| `bus` | 3 | 消息总线分发 |
| `adapter` | 3 | 适配器回调 |
| `async_node` | 2 | 异步节点执行 |
| 其他 | 无限制 | 通用任务 |

最大工作线程数默认 8，线程名前缀 `bt-shared`。

## 3 适配器层 (bt_adapters/)

### 3.1 BaseAdapter 抽象基类

**文件**: `bt_adapters/base.py`

```python
class BaseAdapter(ABC):
    @classmethod
    @abstractmethod
    def get_adapter_level(cls) -> AdapterLevel: ...    # LOCAL / REMOTE / HYBRID
    @classmethod
    @abstractmethod
    def is_available(cls) -> bool: ...                  # 依赖检测
    @abstractmethod
    def start(self) -> None: ...
    @abstractmethod
    def stop(self) -> None: ...
    @abstractmethod
    def get_name(self) -> str: ...
    @abstractmethod
    def get_status(self) -> AdapterStatus: ...
```

### 3.2 AdapterManager 单例

**文件**: `bt_adapters/adapter_manager.py`

管理所有适配器实例的注册、实例化、启停和状态查询。采用双重检查锁定单例，与 `InputControllerManager` 设计一致。

核心方法:
- `register_adapter(name, class)` — 注册适配器类型
- `get_adapter(name)` — 获取适配器实例（自动实例化 + 依赖检测）
- `start_all(message_bus)` — 启动所有适配器并注入消息总线
- `stop_all()` — 停止所有适配器
- `reset_instance()` — 重置单例（测试用）

### 3.3 HTTPAdapter

**文件**: `bt_adapters/http_adapter.py`

基于 `requests.Session` 的 HTTP 适配器，支持重试和超时控制。

| 特性 | 说明 |
|------|------|
| 会话复用 | `requests.Session` 保持连接池 |
| 自动重试 | `max_retries` 次，间隔 `retry_backoff_ms` 毫秒 |
| JSON 请求体 | dict/list 自动序列化为 JSON |
| 响应封装 | `HTTPResponse` 对象包含 status_code、text、headers、elapsed_ms |
| 懒 JSON 解析 | `.json` 属性首次访问时解析，缓存结果 |

### 3.4 WebSocketAdapter

**文件**: `bt_adapters/websocket_adapter.py`

客户端模式 WebSocket 适配器，在独立线程中运行 asyncio 事件循环。

| 特性 | 说明 |
|------|------|
| 自动重连 | 连接断开后按 `reconnect_interval_ms`（5秒）自动重连 |
| 心跳保活 | `ping_interval_ms`（30秒）间隔发送 ping |
| 线程隔离 | 独立线程运行 asyncio loop，不阻塞主线程 |
| 消息回调 | 通过 `connect(url, on_message)` 注册回调 |

### 4.5 AsyncExecutor

**文件**: `bt_utils/async_executor.py`

通过 `SharedThreadPool` 管理异步节点任务，支持超时和取消。

| 方法 | 说明 |
|------|------|
| `submit(node_id, func, timeout_ms)` | 提交异步任务到共享线程池 |
| `is_done(node_id)` | 检查任务是否完成 |
| `get_result(node_id)` | 获取任务结果（未完成返回 RUNNING） |
| `cancel_all()` | 取消所有任务（引擎停止时调用） |

**超时机制**: 提交时记录 deadline，执行前检查是否超时，超时返回 FAILURE。

**取消机制**: `cancel_all()` 将节点 ID 加入 cancelled 集合，`future.cancel()` 取消未开始的任务，正在执行的任务通过 deadline 检查中止。

## 5 认证体系

### 5.1 认证模型

**文件**: `bt_services/auth_service.py`

```python
@dataclass
class AuthPrincipal:
    user_id: str
    username: str = ""
    display_name: str = ""
    roles: List[str] = field(default_factory=list)
    token: str = ""
    scopes: List[str] = field(default_factory=list)
    is_offline: bool = False
```

### 5.2 BaseAuthService 抽象基类

| 方法 | 说明 |
|------|------|
| `verify_token(token)` | 校验 Token，返回 AuthPrincipal 或 None |
| `authenticate(credentials)` | 认证（登录） |
| `is_authenticated()` | 当前是否已认证 |
| `get_current_principal()` | 获取当前认证主体 |
| `has_role(role)` | 检查角色 |
| `has_permission(permission)` | 检查权限（支持通配符 `tree:*`） |
| `logout()` | 登出 |

### 5.3 NoopAuthService

空实现，所有验证都通过，所有权限都允许。消息总线和 REST Server 默认使用此实现，认证未启用时的兜底方案。

### 5.4 PlatformAuthService

对接 `LoginManager` 实现真实平台认证。通过 `login_manager.login()` 登录，`api_client.validate_token()` 校验 Token。

### 5.5 权限矩阵

| 角色 | 权限 |
|------|------|
| `admin` | 全部权限 |
| `operator` | `tree:*`, `blackboard:read/write/list`, `node:status/config`, `event:subscribe`, `adapter:http/websocket` |
| `viewer` | `tree:status`, `blackboard:read/list`, `node:status/config`, `event:subscribe` |
| `anonymous` | 无权限 |

**公开端点**（无需认证）: `/api/v1/auth/login`, `/api/v1/auth/logout`, `/api/v1/auth/status`, `/api/v1/health`

### 6.2 SSE 事件流

通过 `sse-starlette` 实现 Server-Sent Events，订阅 `bt.**.event.**` 主题，将消息总线事件推送给客户端。

**心跳机制**: 30 秒无消息时发送 `ping` 事件保持连接。

### 6.3 WebSocketServer

**文件**: `bt_servers/websocket_server.py`

向客户端广播消息总线事件。客户端通过 query 参数订阅主题：

```
ws://host:port?topic=bt.1.event.**&token=xxx
```

**特性**:
- 主题过滤 — 客户端按 topic 参数过滤接收的消息
- Token 认证 — 可选，通过 auth_service 校验
- 自动清理 — 广播异常的客户端自动移除
- 心跳 — 客户端发送 `{"type":"ping"}`，服务端回复 `{"type":"pong"}`

## 7 接口节点

### 7.1 HTTPRequestNode

**文件**: `bt_nodes/network/http_request_node.py`

发起 HTTP 请求并将响应写入黑板。异步节点（`_is_async = True`）。

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `url` | "" | 请求 URL |
| `method` | GET | GET/POST/PUT/DELETE |
| `body` | "" | 请求体 |
| `headers` | {} | 请求头 |
| `timeout_ms` | 5000 | 超时毫秒 |
| `expected_status` | 0 | 期望状态码（0=不检查） |
| `response_key` | http_response | 黑板键名 |

**适配器优先**: 有 `AdapterManager` 时通过 `HTTPAdapter` 调用（支持重试），否则直接使用 `requests`。

### 7.2 APIConditionNode

**文件**: `bt_nodes/network/api_condition_node.py`

根据 HTTP 响应内容判断条件是否成立。

| 配置项 | 说明 |
|--------|------|
| `json_path` | 响应 JSON 中取值路径（如 `data.code`） |
| `expected_value` | 期望的字段值 |

支持点分路径提取嵌套 JSON（`data.items.0.name`）。

### 7.3 WebSocketNode

**文件**: `bt_nodes/network/websocket_node.py`

WebSocket 客户端节点，支持发送和接收消息。

| 配置项 | 说明 |
|--------|------|
| `url` | ws:// 或 wss:// 地址 |
| `action` | `send` / `recv` |
| `message` | send 模式发送的字符串 |
| `payload_key` | recv 模式写入黑板的键名 |
| `timeout_ms` | recv 超时（默认 1000ms） |

**连接复用**: 类级 `_connections` 字典缓存 URL→连接映射，per-URL 锁防止竞态。`close_all_connections()` 在 GUI 退出时清理。

### 7.4 MessagePublishNode

**文件**: `bt_nodes/message/publish_node.py`

向消息总线发布消息。

| 配置项 | 说明 |
|--------|------|
| `topic` | 主题（自动加 `bt.{tree_id}.` 前缀） |
| `payload` | 静态负载字典 |
| `payload_key` | 黑板键名（优先使用黑板值覆盖 payload） |
| `prefix_tree_id` | 是否自动加前缀（默认 True） |

### 7.5 MessageSubscribeNode

**文件**: `bt_nodes/message/subscribe_node.py`

等待并接收消息总线上的消息，写入黑板。

| 配置项 | 说明 |
|--------|------|
| `topic` | 订阅主题（支持通配符） |
| `payload_key` | 消息 data 写入黑板的键名 |
| `timeout_ms` | 等待超时（blocking 模式生效） |
| `wait_mode` | `blocking` / `nonblocking` |

**生命周期**: `on_start()` 订阅主题 → `_execute_action()` 检查消息 → `reset()` / `abort()` 取消订阅。支持懒订阅（首次 tick 时订阅）。

## 8 Headless 模式

**文件**: `bt_core/headless.py`

`HeadlessRunner` 提供无 GUI 运行能力，完整启动流程：

1. 注册所有节点 → `register_all_nodes()`
2. 加载行为树文件 → 反序列化为节点树
3. 创建 `ExecutionContext` → `set_headless(True)`
4. 创建 `BehaviorTreeEngine`
5. 启动服务层:
   - MessageBus 单例 → 注入 Context
   - AdapterManager 单例 → `start_all(bus)`
   - ServiceRegistry → 注册 Data/Tree/Node/Auth/AsyncExecutor 服务
   - RESTServer (uvicorn) → 独立守护线程
   - WebSocketServer → `attach_bus(bus)`
6. 启动引擎
7. 等待停止信号（Ctrl+C 或 `stop()`）
8. 停止服务层 → 逆序清理资源

---

## 9 异步节点执行

### 9.1 引擎集成

`BehaviorTreeEngine` 通过以下机制支持异步节点：

1. **`_async_executor`**: 引擎持有 `AsyncExecutor` 实例
2. **`_engine_thread_id`**: 记录引擎线程 ID，注入 MessageBus 防死锁
3. **`_is_async` 标志**: 节点通过设置 `self._is_async = True` 声明为异步
4. **异步 tick 流程**: 引擎检测到 `_is_async=True` 时，首次 tick 提交任务到 AsyncExecutor，后续 tick 轮询 `is_done()` + `get_result()`
5. **引擎停止**: `stop()` 时调用 `_async_executor.cancel_all()` 取消所有异步任务

### 9.2 Blackboard 事件发布

`Blackboard.set()` 注入 MessageBus 后，每次变量变更自动发布 `bt.{tree_id}.data.blackboard.changed` 事件，外部系统可订阅监听。

## 10 CodeNode 安全修复

**文件**: `bt_nodes/actions/code.py`

修复了 import 检查漏洞，采用双重防护：

| 机制 | 说明 |
|------|------|
| `ALLOWED_MODULES` | 白名单，仅允许导入安全模块（如 `math`, `json`, `time`） |
