## 1 背景与目标

### 1.1 当前状态

前三阶段已完成 CLI 核心能力（5 阶段流水线 + 9 个 CLI 命令 + 66 个测试全部通过）。用户可通过 `autodoor-bt ai create` 等命令行方式完成 AI 行为树编排。

### 1.2 第四阶段目标

| 目标 | 说明 |
|------|------|
| GUI 内嵌 AI 助手面板 | 在行为树编辑器右侧新增可折叠侧栏，用户在 GUI 内完成 5 阶段流程 |
| 画布上直接标注 VLM 识别的区域 | VLM 分析截图后，在 Canvas 上叠加半透明标注，用户可拖拽微调 |
| 可视化迭代修正流程 | 试运行后在侧栏展示报告、失败节点、AI 修正建议，用户可视化确认 |

### 1.3 设计原则

- **复用 CLI 核心模块**：GUI 层只负责交互编排和结果展示，业务逻辑全部复用 `bt_cli/ai/` 下已实现的模块
- **不侵入编辑器核心**：AI 助手面板作为独立组件插入编辑器布局，不修改 Canvas/PropertyPanel/Palette 的核心逻辑
- **异步执行**：所有 LLM/VLM 调用在后台线程执行，不阻塞 GUI 主线程
- **可折叠**：AI 助手面板默认收起，不永久占用编辑器空间

## 3 面板交互设计

### 3.1 面板内部布局

```
┌─ AI 助手 ──────────────────────┐
│ × 关闭                          │
│                                │
│ ┌─ 阶段进度 ─────────────────┐  │
│ │ ①意图→②选型→③感知→④生成→⑤试运行│
│ └────────────────────────────┘  │
│                                │
│ ┌─ 当前阶段内容区 ───────────┐  │
│ │                            │  │
│ │  (随阶段切换内容)            │  │
│ │                            │  │
│ └────────────────────────────┘  │
│                                │
│ [上一步]  [确认并下一步]        │
└────────────────────────────────┘
```

### 3.2 五阶段交互

| 阶段 | 面板内容 | 用户操作 | 完成后 |
|------|---------|---------|--------|
| ① 意图分析 | 文本输入框 + "分析"按钮 | 输入自然语言描述，点击分析 | 显示 plan.json 摘要，确认→② |
| ② 节点选型 | 节点结构树形预览 | 查看节点列表和连接关系 | 确认→③ |
| ③ 屏幕感知 | 截图预览 + 参数建议表 | 自动截图，VLM 分析后显示建议值和置信度，可手动修改 | 确认→④ |
| ④ 生成 JSON | 生成结果摘要 | 显示节点数/连接数/校验状态 | 确认→⑤，生成后自动加载到画布 |
| ⑤ 试运行 | 试运行报告 + 修正建议 | 显示成功/失败、日志、AI 修正建议，可确认应用修正 | 迭代或完成 |

### 3.3 阶段进度指示器

顶部水平进度条，5 个圆形节点用连线连接：
- 已完成阶段：绿色实心圆 ✓
- 当前阶段：蓝色脉冲圆点
- 未开始阶段：灰色空心圆

用户可点击已完成的阶段回退查看，但不能跳过未完成阶段。

### 3.4 异步执行与状态管理

所有 AI 操作在后台线程执行：
1. 用户点击操作按钮 → 面板显示加载动画 + "正在分析..."
2. 后台线程调用 CLI 模块 → 完成后通过 `threading.Event` 通知主线程
3. 主线程更新 UI 展示结果

```python
# 状态流转
class AssistantState:
    stage: int = 0                    # 当前阶段 0-5
    plan: dict = None                 # 阶段①输出
    structure: dict = None            # 阶段②输出
    filled_structure: dict = None     # 阶段③输出
    tree_data: dict = None            # 阶段④输出
    test_report: dict = None          # 阶段⑤输出
    is_processing: bool = False       # 是否正在处理
```

## 4 画布区域标注

### 4.1 CanvasOverlay 组件

VLM 分析截图后，在 Canvas 上叠加半透明覆盖层标注识别到的坐标区域：

```
┌─ Canvas ──────────────────────────┐
│                                   │
│   ┌─────░░░░─────┐                │
│   │  ░░ 绿色框 ░░│  ← region 标注  │
│   │  ░░置信度95%░│                │
│   └─────░░░░─────┘                │
│              ● ← position 标注     │
│                                   │
└───────────────────────────────────┘
```

### 4.2 标注类型

| 参数类型 | 标注形式 | 颜色 |
|---------|---------|------|
| region [x1,y1,x2,y2] | 半透明矩形 + 四角拖拽点 | 绿色（高置信度）/ 橙色（低置信度） |
| position [x,y] | 圆形标记点 + 十字线 | 蓝色 |
| template_path | 矩形边框（不填充） | 紫色 |

### 4.3 交互

- **点击标注**：选中后在 PropertyPanel 中高亮对应参数
- **拖拽微调**：拖拽矩形边框/角点调整 region 范围，修改后自动回填到 structure
- **清除标注**：切换阶段或关闭面板时自动清除
- **标注层独立**：标注绘制在 Canvas 的 tkinter Canvas 对象上，独立于节点图形，不参与节点选择/连线逻辑

### 4.4 坐标映射

VLM 返回的坐标基于截图分辨率，Canvas 上的坐标基于画布坐标系。需要处理：
- 截图分辨率 → Canvas 显示坐标的缩放比例
- Canvas 缩放（zoom）和平移（pan_x/pan_y）的变换

```python
def screenshot_to_canvas(x, y, screenshot_size, canvas_viewport):
    """截图坐标 → Canvas 坐标"""
    scale_x = canvas_viewport.width / screenshot_size[0]
    scale_y = canvas_viewport.height / screenshot_size[1]
    return x * scale_x, y * scale_y
```

## 5 迭代修正可视化

### 5.1 试运行报告展示

```
┌─ 试运行报告 ─────────────────────┐
│ ✓ 成功 / ✗ 失败                   │
│                                  │
│ 执行日志（最后 10 行）：           │
│  [SequenceNode] 执行子节点...      │
│  [OCRConditionNode] 识别失败       │
│  [MouseClickNode] 点击完成         │
│                                  │
│ ┌─ AI 修正建议 ───────────────┐   │
│ │ 节点: node_detect           │   │
│ │ 参数: region                │   │
│ │ 原值: [100,200,200,250]     │   │
│ │ 建议值: [100,200,400,400]   │   │
│ │ 原因: 扩大识别区域           │   │
│ │ [应用] [跳过]               │   │
│ └─────────────────────────────┘   │
│                                  │
│ [重新试运行]  [完成]              │
└──────────────────────────────────┘
```

### 5.2 修正建议交互

- 每条修正建议独立展示为卡片，包含节点 ID、参数名、原值、建议值、原因
- 用户可逐个"应用"或"跳过"
- 应用修正后自动在画布上更新对应节点的参数显示
- 可选择"重新试运行"进入下一轮迭代

### 5.3 迭代限制

- 最大迭代次数从配置 `ai.iteration.max_rounds` 读取（默认 3 次）
- 每轮迭代结果保存在面板状态中，可回看
- 达到最大次数后显示"已达最大迭代次数"提示

## 6 错误处理

| 场景 | 处理方式 |
|------|---------|
| 未配置 API Key | 面板显示配置提示，链接到设置页面 |
| LLM/VLM 请求超时 | 显示错误信息，提供"重试"按钮 |
| LLM 返回无效 JSON | 显示原始返回内容，提供"重试"按钮 |
| 试运行超时 | 标记为失败，AI 分析超时原因 |
| 截图失败 | 显示错误信息，允许手动上传截图 |
| 节点选型校验失败 | 显示校验错误列表，提供"重新选型"按钮 |
